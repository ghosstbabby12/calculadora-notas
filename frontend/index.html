    1 Arquitectura viva

    El navegador nunca conoce la URL interna de la API: pide todo a Nginx, que reenvía /api/* al backend. Cada caja es un contenedor de Docker Compose.

    1. Navegador HTML + JS (fetch)
    2. Nginx :8080 · proxy /api
    3. Gunicorn :5000 · 1 worker, 8 hilos
    4. calculadora.py pesos 30 / 30 / 40
    5. LocalStack S3 :4566 · reporte CSV
    API: verificando… Latencia: — S3 se comprueba al exportar

    Por qué importa: Nginx sirve archivos estáticos y enmascara la API; Gunicorn reemplazó al servidor de desarrollo de Flask, que se quedaba sin conexiones a partir de 800 usuarios (ver load/informe.md).

    6 Decisiones técnicas

    ¿Por qué Nginx delante de la API?
    Sirve el frontend y reenvía /api; el navegador no necesita CORS ni conocer el puerto interno.
    ¿Por qué Gunicorn y no flask run?
    El servidor de desarrollo cerraba conexiones a partir de 800 usuarios. Gunicorn atiende en un proceso con hilos.
    ¿Por qué 127.0.0.1 y no localhost?
    En macOS AirPlay ocupa el puerto 5000 y responde 403 a localhost.
    ¿Dónde se pierde el estado?
    Los estudiantes viven en un diccionario en memoria: al reiniciar la API se pierden. El CSV en S3 es la persistencia del reporte.
    ¿Por qué 80 % de cobertura?
    Es el mínimo de pytest.ini: obliga a cubrir ramas de error, no solo el camino feliz.
